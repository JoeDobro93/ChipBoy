# ChipBoy parameters, in host order

Generated by `tools/demo/make_demo.py`. The order is the order
`Source/plugin/shared/Parameters.cpp` adds the parameters: the globals from
`addGlobalParameters`, then channels 1-4 from `addChannelParameters`. Every
channel has the same fifteen -- source, instrument, table, level, pan,
transpose, two command slots of three parameters each, live follow, velocity
and keyswitches -- and only Level differs between the kinds (0-16 on the
pulse and noise channels, 0-4 on the wave channel). JUCE presents the list to
VST3 hosts in exactly this order; the wrapper's own Bypass parameter and,
after it, its MIDI CC emulation parameters follow the 76 below.
`chipboy_paramdump` (a CMake target of the plugin build) prints the same table
from the running code, and `make_demo.py --paramdump <path>` checks this file
against it.

The **index** is what Reaper's `PARMENV` lines use. The **VST3 id** is what
JUCE derives from the id string (`String::hashCode()` with the top bit
cleared); Reaper writes it after the index (`index:id`) so an envelope
survives a change of order. Envelope values are normalised: for an
integer or choice parameter the stored value is `(v - min) / (max - min)`,
and the plugin rounds to the nearest step when it reads it back.

## The two command slots

A slot is three parameters -- the letter, `x` and `y` -- and it is *in force*
rather than momentary. It fires at the next tick whenever one of the three
changes, and again at every note-on, after the instrument and its table, so a
letter drawn across a bar shapes every note in that bar. Put the letter back
to `none` and what it changed reverts to the instrument's own value (`E` `F`
`O` `S` `V` `W`), to zero (`P`), to the parameter (`M`), or stops (`A`, `G`).
CMD1 is applied before CMD2.

| Letter | Meaning | x | y |
|---|---|---|---|
| `A` | table | table slot 1-64, 0 stops | - |
| `C` | chord | semitones | semitones |
| `D` | delay | ticks | - |
| `E` | envelope | volume 0-15 (wave level 0-3 on WAV) | 0-7 decay, 8-15 attack |
| `F` | frame | frame 1-16 (WAV) | - |
| `G` | groove | groove slot 1-16, 0 straight | - |
| `K` | kill | ticks after the note-on | - |
| `L` | slide | rate 0-15 | - |
| `M` | master volume | left 0-7 | right 0-7 |
| `O` | pan | 0 off, 1 L, 2 R, 3 both | - |
| `P` | pitch offset | 0-255, signed x - 128 period units | - |
| `R` | retrigger | volume step per retrigger | every y ticks |
| `S` | sweep (PU1) | rate 0-7, +128 for down | shift 0-7 |
| `T` | tempo | 40-255 BPM, Song source only | - |
| `V` | vibrato | speed 1-15 | depth 0-15 |
| `W` | wave | duty 0-3 on a pulse, wave slot 1-64 on WAV | - |
| `Z` | random | randomises the other slot's x, up to x | - |

`H` (hop) exists in table steps only, so it is not in the lane's choice; the
full definitions are in [`../docs/COMMANDS_AND_TEMPO.md`](../docs/COMMANDS_AND_TEMPO.md)
section 2.

## The rest of the channel

Three fields carry a position meaning "use the instrument's value": the top
value of Level (16, or 4 on WAV), the `inst` choice of Pan, and 0 of Table.
Automation overrides the instrument only where a lane is drawn away from that
position. Everything a lane used to override silently -- duty, envelope,
sweep, wave, frame, vibrato, arpeggio, detune, LFSR width -- is now the
instrument's alone, or arrives as a command.

Ticks are 24 to the beat, from **Tempo Source** (`tempo_source`): the host's
tempo, or the song's own **Song Tempo** (`song_tempo`, 40-255 BPM) with `T`
commands over it. **Quantise Notes To Ticks** (`notes_on_tick`) holds incoming
note-ons and note-offs until the next tick; bends and controllers are never
quantised, and tracker cells are always on ticks.

## What the demo automates

`ChipBoy Demo.rpp` draws `ch1_source`, `ch3_keyswitch`, `ch4_keyswitch`,
`ch4_velocity`, `ch2_instrument`, `ch1_cmd1_type`, `ch1_cmd1_x`,
`ch1_cmd2_type`, `ch1_cmd2_x`, `ch1_cmd2_y`, `ch2_cmd1_type`, `ch2_cmd1_x`,
`ch2_cmd1_y`, `ch3_cmd1_type`, `ch3_cmd1_x`, `ch3_cmd2_type`, `ch3_cmd2_x`,
`master_l`, `master_r`, `declick`, `model`.

`ChipBoy Demo (song tempo).rpp` draws the same lanes plus `tempo_source`,
`song_tempo`, and PU1's second slot carries `T` for bars 9-12 instead of going
back to none at bar 9.
